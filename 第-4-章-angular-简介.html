    5. 第 4 章 - [Angular] 简介

    5.1. 来源

    本章基于 [Angular] 的官方文档：angular.dev。

    5.2. 从 AngularJS 1.x 到 [Angular]

    原始文档（2014 年）使用的是AngularJS 1.x：一个围绕 $scope、控制器、指令（ng-repeat、ng-if……）组织的框架（JavaScript——尚未使用 TypeScript），其变更检测机制基于“脏检查循环”（$digest）和变量监视（$watch）。

    从 2016 年开始，该框架以 [Angular] （不带“JS”）的名称，使用 TypeScript 被彻底重写，采用基于组件的架构。后续版本陆续发布（2、4……直到本文档使用的 22），在处理 [RdvMedecins] 客户端代码之前，你需要了解其中两个重大变化：

    • 逐步淘汰NgModules （@NgModule），转而采用独立的、自包含的组件；
    • 引入信号 （signal()），一种取代 $watch/$digest 的新响应式模型。

    本章将逐一介绍这些概念，并配以独立于案例研究的简短示例——下一章将在完整的 [RdvMedecins] 客户端中演示它们的实际应用。

    5.3. [Angular] 应用程序的概念：“单页应用”

    [Angular] 应用是一个单页应用（SPA，SPA）：服务器只向浏览器发送一个页面（HTML），其中包含一个封装了应用全部逻辑的 JavaScript 文件。该页面加载完成后，不再进行整页重新加载：用户的每一次交互（切换视图、提交表单等）都由浏览器中已有的 JavaScript 代码处理，由它更新显示内容，并通过异步 HTTP 请求（通常使用 JSON）在后台与服务器通信。这正是原文档中 AngularJS 1.x 的原理，至今没有改变。

    5.4. 组件

    组件是 [Angular] 应用的基本单元：它将视图（HTML 模板）与负责管理其状态和行为的 TypeScript 类关联起来——这正是原文档中 AngularJS 1.x 的“视图 + 控制器”这一对所扮演的角色，只是在这里二者合并成了一个实体。

    下面是一个与案例研究无关的非常小的组件，可以通过 ng generate component counter 创建：

    // counter.component.ts
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-counter',
  templateUrl: './counter.component.html',
})
export class CounterComponent {
  readonly value = signal(0);

  increment(): void {
    this.value.update((v) => v + 1);
  }
}
<!-- counter.component.html -->
<p>Value: {{ value() }}</p>
<button (click)="increment()">+1</button>
    • 第 4 行：[@Component]({...}) 是一个装饰器（与 [NestJS] 中的机制相同，参见第 2 章），它将下面的类声明为 [Angular] 组件；
    • 第 5 行：selector: 'app-counter'：自定义 HTML 标签（<app-counter>）的名称，在其他组件的模板中使用该标签时，会在该位置插入此组件——这就是视图组合机制，在 AngularJS 1.x 中已经存在（形式不同，即指令）；
    • 第 6 行：templateUrl：与该组件关联的 HTML 文件（也可以使用 template 属性，直接在装饰器中编写 HTML）；
    • 第 9 行：signal(0) 创建一个响应式值，初始值为 0（见下一节）；
    • 第 16 行：模板中的 {{ value() }}：双花括号显示由类计算出的值——语法与AngularJS 1.x 相同，但请注意括号：`value` 是一个信号，因此是一个必须调用才能读取其当前值的函数；
    • 第 17 行：(click)="increment()"：`click` 两边的括号表示“监听 `DOM` 的 click 事件”并调用指定的方法——与 `AngularJS` 1.x 中的 `ng-click` 指令完全等价。

    5.5. 信号：新的响应式模型

    在 AngularJS 1.x 中，[Angular] 通过一个系统化的检查循环（$digest）来检测数据变化，该循环会在每次可能的交互时遍历所有被监视的表达式（$watch）。这种机制虽然使用简单，但随着应用规模增长，开销会变得很大。

    信号是一个值容器，它知道自己何时发生变化，并且知道有哪些内容依赖于它（模板、另一个计算等）——因此 [Angular] 不再需要重新检查所有内容：只有真正依赖于已修改信号的那部分应用才会被重新计算。掌握基础只需要三个函数：

    函数
    作用
    mySignal(initialValue)
    创建一个信号；通过将其作为函数调用来读取其值：mySignal()
    mySignal.set(newValue)
    替换信号的值
    mySignal.update(v => ...)
    基于旧值计算新值（参见上面的 increment()）
    computed(() => ...)
    创建一个由其他信号自动计算得出的信号，并且仅在必要时才重新计算

    signal() 的两个特化变体用于使组件与其父组件通信——它们在 [RdvMedecins] 客户端中频繁出现（见下一章）：

    • input()（及其变体 input.required()）声明一个输入：由父组件提供的值。这是传统 @Input() 装饰器的现代演进，在概念上等同于 AngularJS 1.x 指令的属性；
    • output() 声明一个输出：组件可以向其父组件发出的事件（使用 .emit(value) 方法）。这是 @Output() / EventEmitter 的现代演进，等同于 AngularJS 1.x 的自定义事件（$emit）。

    5.6. 独立组件

    AngularJS 1.x 应用由模块（angular.module(...)）组织，在其中声明控制器、指令和服务。[Angular] 最初以一种更为刚性的形式（NgModule，即 @NgModule 装饰器）采用了这一思想，随后在近期版本中引入了独立组件——它们此后已成为默认的工作模式。

    独立组件在其自身的 [@Component] 装饰器中声明它所需的一切——例如模板中使用的其他组件——而不是依赖共享模块：

    1

    @Component({
  selector: 'app-parent',
  imports: [CounterComponent], // 模板中使用的组件
  templateUrl: './parent.component.html',
})
export class ParentComponent {}

    [RdvMedecins] 客户端自始至终都采用这种风格：其中不再出现任何 *.module.ts 文件，与 AngularJS 1.x 以及早期版本的 Angular 相比，这都是一个显著的简化。

    5.7. 服务与依赖注入

    与 [NestJS]（第 2 章）中一样，[Angular] 的服务是一个由 [@Injectable] 装饰的普通类，[Angular] 可以自动创建它并将其提供给任何需要它的组件——这与前述依赖注入的概念相同，事实上，AngularJS 1.x 正是最早推广这一原则的 JavaScript 框架之一（[NestJS] 直接受其启发也并非巧合，如第 2 章所述）。

    1
2
3
4
5
6
7
8
    import { Injectable } from '@angular/core';

@Injectable({ providedIn: 'root' })
export class MyService {
  greet(): string {
    return 'Hello';
  }
}
    • 第 3 行：providedIn: 'root' 表示整个应用只创建该服务的一个实例（单例）——相当于 AngularJS 1.x 中的 .service() 或 .factory()。

    要在组件中获取该服务，现代 [Angular] 提供了 inject() 函数，它取代了传统的构造函数注入（两者仍然都可用，但 inject() 已成为标准做法，[RdvMedecins] 客户端使用的就是它）：

    1
2
3
4
5
6
7
    import { Component, inject } from '@angular/core';
import { MyService } from './my.service';

@Component({ ... })
export class MyComponent {
  private readonly myService = inject(MyService);
}

    5.8. 与服务器通信：[HttpClient]

    [HttpClient]（[@angular/common/http]）模块允许你向服务器发送 HTTP 请求——GET、POST……——并处理其响应。它是原文档所使用的 AngularJS 1.x 中 $http 服务的直接演进。

    1
2
3
4
5
6
7
8
    import { inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';

const http = inject(HttpClient);
http.get<{ message: string }>('http://localhost:8080/hello').subscribe({
  next: (response) => console.log(response.message),
  error: (error) => console.error(error),
});

    与 $http 的一个重要区别是：[HttpClient] 的方法（get、post……）并不直接返回响应，也不像人们可能预期的那样返回 Promise，而是返回一个Observable（RxJS 库）——一个随时间变化的值流，你通过 .subscribe({ next, error }) 订阅它，以便在响应到达（或发生错误）时得到通知。你还可以在订阅之前使用运算符（如 map）对 Observable 进行转换：

    1
2
3
    http.get<{ message: string }>('...').pipe(
  map((response) => response.message), // we only keep the "message" field
);

    [RdvMedecins] 客户端（下一章）的 [AppointmentService] 服务始终使用这种 .pipe(map(...)) 组合，原因将在那里解释。

    5.9. 新的流程控制语法：[@if] 和 [@for]

    AngularJS 1.x 使用结构型指令（ng-if、ng-repeat）来有条件地显示元素，或为列表中的每个元素重复一个模板块。[Angular] 长期以来使用与之非常相似的等价写法（*ngIf、*ngFor），之后在其近期版本中引入了集成在模板语言本身中的语法——也就是整个 [RdvMedecins] 客户端所使用的语法：

    <li>{{ item.name }}</li>
  }

    • 第 8 行：track item.[id]（[@for] 要求必须提供）告诉 [Angular] 在重绘列表时如何识别已经显示过的元素——这很像 ng-repeat 中就已经可以（作为可选项）使用的“track by”。

    5.10. 小结：AngularJS 1.x -> [Angular] 对照表

    AngularJS 1.x（2014）
    [Angular]（2026）
    Controller + $scope
    组件（类 + 模板）
    $watch / $digest 循环
    信号（signal()、computed()）
    angular.module(...)、@NgModule
    独立组件
    @Input() / @Output()（传统方式）
    input() / output()（信号）
    .service() / .factory()
    [@Injectable]({ providedIn: 'root' })
    构造函数注入
    inject()（或仍通过构造函数）
    $http
    [HttpClient]（Observables RxJS）
    ng-if / ng-repeat
    [@if] / [@for]
    JavaScript
    TypeScript
