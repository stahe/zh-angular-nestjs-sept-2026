    ==

    本文档是 2014 年所写课程 “客户端/服务器示例 — AngularJS 1.x / Spring 4，” 的续篇。那份原始文档使用 Spring 4 / Spring Data / Spring MVC 服务器和 AngularJS 1.x 客户端构建了一个小型的预约就诊日程应用（“[RdvMedecins]”）。

    十二年过去了，所用的两个框架已发生重大演变，甚至在常用场景中已被取代：

    • 在服务器端，[NestJS] 已成为构建结构化 Web 应用时使用最广泛的 Node.js/TypeScript 框架之一，其理念与 Spring 相似（模块、控制器、服务、依赖注入），但处于 JavaScript/TypeScript 生态之中；
    • 在客户端，AngularJS 1.x 自 2016 年起以 [Angular] （2、4、5……直至本文档使用的 22 版）之名被彻底重写，采用基于组件的架构，近来更引入了 基于信号的响应式系统，取代了 AngularJS 1.x 的监视机制（$watch）。

    本文档的目标是重温最初的案例研究——同一个应用、同样的功能、同一个数据库——并 使用当前的工具重新构建它，同时尽可能保持与 2014 年文档相同的教学进度。

    1.1. 分步重构

    原始文档约有 300 页，除应用的核心功能——基于角色的身份验证（Spring Security）——之外，还包含十二个循序渐进的示例，用于分步学习 AngularJS 1.x。一次性重构所有这些内容既耗时又难以消化。

    因此，本文档涵盖重构的 前两个步骤 ：

    • 应用的总体架构（原则上不变）；
    • 数据库（不变，只是增加了 [users] 表）；
    • 完整的 [NestJS] 服务器，具备查看以及预约/取消预约的全部功能；
    • 基于令牌的身份验证（JWT）和基于角色的访问控制 （ADMIN/USER），相当于原始文档中的 Spring Security 层；
    • 相应的 [Angular] 客户端，功能相同，带有登录界面、根据已登录用户角色定制的 Bootstrap 界面，并可在法语和英语之间切换界面语言（[@ngx-translate/core]）。

    原始文档中的两项功能在现阶段不包含在本文档中：原始客户端的“调试”模式（显示当前视图的原始模板），在本次移植中已被 有意省略（这一决定的理由见第 6 章），以及人为网络延迟的配置，该功能推迟到后续阶段。

    1.2. 本文档面向的读者

    本文档不要求读者事先了解 [NestJS] 或 Angular。每个新概念（装饰器、依赖注入、组件、信号等）在出现时都会尽可能详细地加以解释，即使是从未写过一行 TypeScript 的读者也能理解。

    不过，掌握一些基础知识有助于更好地理解本文档：

    • 对 JavaScript 语言（变量、函数、数组、对象）有基本了解；
    • 对 Web 应用中的 HTTP 交互（GET/POST 方法、JSON 格式）有基本了解；
    • 了解 HTML 语言的常用标签；
    • 会使用命令行（cd、npm install……）。

    您无需事先熟悉 TypeScript 语言（服务器端和客户端都使用它）：它是 JavaScript 的超集，增加了类型系统，文档在每次用到时都会对其加以说明。有兴趣的读者可以参阅文档 [Introduction to the TypeScript language and the NestJS web framework through examples (2026)]，其中详细讲解了 TypeScript。

    1.3. 应用的架构

    应用的总体架构自原始文档以来没有改变：

    • Web 服务器提供一个单一的 HTML/CSS/JS 页面，其中包含一个基于 组件模型（视图 + 相关逻辑）构建的 [Angular] 应用，该应用依靠 服务 与服务器通信；
    • 用户与浏览器中显示的视图交互。用户的操作有时需要向 [NestJS] 服务器发出请求，服务器处理请求并返回 JSON （JavaScript Object Notation）响应；该响应用于更新呈现给用户的视图。

    所考察的应用将具有如下架构：

    • 在 [1] 中，[Angular] 应用的用户向该应用的 [presentation] 层 [2] 发出查询；
    • 为了执行用户请求的操作，[presentation] [2] 层可以查询 [Services] [3] 层；
    • 为了提供所请求的服务，[3] 层可能需要查询 [4]，即由 [NestJS] 实现的远程 JSON 服务器；
    • 根据在 [5] 中收到的请求，可能会查询 [6-8] 各层；
    • 服务器的响应按相反的顺序经过 [2-8] 各层返回；
    • 显示给用户的视图 [1] 反映了该响应；

    注意：如果您对项目的架构感到困惑，请回头参考这张图。请注意，DBMS 由服务器处理，而不是由客户端处理。

    1.4. 使用的工具

    本文档使用以下工具（其安装方法在第 2 章详述）：

    • Node.js （22 或更高版本）及其包管理器 npm——在 JavaScript 生态中，相当于原始 Spring 服务器所用的 Java + Maven；
    • Visual Studio Code，一个免费的代码编辑器，及其 TypeScript 扩展——相当于原始文档中使用的 Spring Tool Suite（STS）和 WebStorm；
    • [NestJS] 的 CLI （[@nestjs/cli]）和 [Angular] 的 CLI（[@angular/cli]），这两个命令行工具用于生成项目结构并启动开发服务器；
    • [MySQL] 8 用于数据库（原始文档使用的是 [MySQL] 5——关系模式本身保持不变）；
    • Postman （或任何其他 HTTP 客户端），用于测试服务器对 POST 请求（/addAppointment、/deleteAppointment）的 URL 响应——浏览器只能测试 GET 请求。

    1.5. 应用的功能

    [RdvMedecins] 应用的“业务”功能与原始文档相比 保持不变；不过，访问控制比原版略为稳健（见下表）：

    • 一家医疗诊所雇用多位医生，每位医生都有各自的就诊时间段；
    • 用户必须登录（用户名/密码）才能访问应用；
    • 登录后，用户可以选择一位医生和某一天，并查看该医生当天的日程：每个时间段显示为可预约或已被预约；
    • 角色为 ADMIN 的用户还可以为其选择的患者预约一个空闲时间段，并取消已有的预约；
    • 角色为 USER 的用户可以查看日程，但不能预约或取消（只读访问）——这是与原始文档有意设置的差别：在原始文档中，USER 角色仅用于演示访问被拒绝的情形，什么也看不到（这一选择的理由见第 3 章“身份验证”一节）。

    1. [NestJS] 简介——框架基础（模块、控制器、提供者），并通过一个迷你项目入门。
    2. [RdvMedecins] 应用的 [NestJS] 服务器——数据库、[TypeORM] 实体、DAO 层、业务层、Web 层，以及基于 JWT 令牌的身份验证和角色。
    3. [Angular] 简介——当前框架的基础（组件、信号、服务和 HTTP 通信）。
    4. [RdvMedecins] 应用的 [Angular] 客户端——客户端架构、各个组件（包括登录界面）、Bootstrap 界面、界面在法语和英语之间的切换，以及对整个应用的分步演练。
